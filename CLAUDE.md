## What this is

`radar`: four scheduled jobs that run on the monthly $100 Claude API credits (Max plan), each producing a Markdown report published to the internal CodiMD.

| Job | Schedule (Asia/Taipei) | Models |
| --- | --- | --- |
| `reddit_digest` (built) | daily 07:15, so the note exists before 08:00 | Haiku 5.5 scores, Sonnet 5.5 summarizes posts and comments |
| `pr_stats` (built; merged PRs per member and ISO week, trend on `/prs`) | daily 06:30 | none |
| `dev_weekly` (built; GitHub PRs/issues of the repos in `config/repos.yaml`) | Mon 09:00 | Sonnet 5.5; Opus 5.5 only for diffs of PRs with a short description (<50 words) and >100 changed lines |
| `changelog_watch` (built; Claude Code, Claude API, herdr, skills/plugin marketplaces) | Fri 09:00 | Haiku 5.5 diff triage, Sonnet 5.5 summary |
| `amp_compare` (competitor feature matrix per AMP workspace) | monthly or manual | Sonnet extracts, Opus 5.5 aligns and analyzes, Fable 5.1 for `--deep` |

## Commands

Node 24 runs the TypeScript directly (type stripping, no build step), so only erasable syntax is allowed: no `enum`, no `namespace`. Import local files with the `.ts` extension.

```
npm test                                   # node:test, all of tests/
node --test tests/redditRun.test.ts        # one file
node --test --test-name-pattern="seen" tests/redditRun.test.ts   # one test by name
npm run typecheck                          # tsc --noEmit
npm run lint                               # biome check . ; add --write to fix
npm run digest -- --date 2026-11-04 --no-upload   # run the job without publishing
GITHUB_TOKEN=$(gh auth token) npm run pr-stats -- --from 2025-11-01 --to 2026-11-04   # refetch every week touched by the range
```

Docker: `mkdir -p state output`, copy `.env.example` to `.env` and fill it, then `docker compose up -d --build`. Create `state/` and `output/` first: Docker would otherwise create them as root and the container's `node` user could not write. The Dockerfile deliberately avoids BuildKit-only features (`ADD --checksum`), because the dev machine has no BuildKit.

Status page: the `web` service (same image, `node web/statusServer.ts`) serves `http://<host>:8080` on the LAN without login: this month's cost against the $100 budget, cost per job, and the last 30 runs with result, error, warnings, cost and note link. It only reads `output/cost.jsonl` and `output/runs.jsonl` (mounted read-only) and has no access to the Docker socket. At the top it shows per job how long ago the last successful run started, in red when older than that job's limit (`MAX_AGE_HOURS` in `web/statusServer.ts`, 26 hours for the daily jobs and 8 days for `changelog_watch`): a schedule that never fired leaves no run record, so this is the only sign of it. Add a limit there for every new job. An overdue or failing job's line also names its latest failure, warnings open in place, and a spend above the budget turns red. Visual rules for both pages are in `DESIGN.md` (product context in `PRODUCT.md`), and `.impeccable/critique/` holds local design-review snapshots that are not committed. Full job logs are not in it: use `docker compose logs -f jobs`.

## Architecture

- `jobs/<name>.ts`: one file per job. It exports its steps plus a `run(options, deps)`, and the CLI at the bottom runs only under `import.meta.main`. `deps` (`fetch`, `sleep`, `now`, `call`, `publish`) is injected so tests never touch the network or the API.
- `lib/claude.ts`: `call()` wraps the Messages API (system prompt cached, optional JSON schema via `output_config.format`) and appends every call to `output/cost.jsonl`; `runCost(job, since)` sums one run for the note footer. The price table is hard-coded there.
- `lib/runLog.ts`: `recordRun(job, work)` wraps a job's CLI entry (config loading included) and appends one record to `output/runs.jsonl` for every run, also a failed one, then rethrows so the exit code stays non-zero. `run()` of a job returns `{ url, warnings }` for it. `web/status.ts` (pure page rendering and month totals in Asia/Taipei time) and `web/statusServer.ts` build the status page from those two files.
- `lib/codimd.ts`: `publish(alias, markdown)`. See the next section.
- `lib/noteIndex.ts`: `withIndex(job, work, publish)` wraps a job's work in its CLI, and after a run that published a note rebuilds the note `radar-index` from `runs.jsonl` plus this run (one section per job, newest first, 30 notes each). A failed update or an index edited on the web becomes a warning on the run, never a failure. Wrap every new job that publishes a note.
- `lib/state.ts`: JSON files under `STATE_DIR` (default `state/`, or another directory passed as the last argument), written atomically. `lib/render.ts`: note layout (title, `> ⚠️` warnings, body, cost line).
- Directories come from env with these defaults: `STATE_DIR=state`, `OUTPUT_DIR=output`, `PROMPTS_DIR=prompts`, `CONFIG_DIR=config`. `state/`, `output/`, `config/`, `prompts/` are volumes in compose, so prompts and config change without a rebuild.
- Pipeline of `reddit_digest`: collect feeds (a post's position in a `/top.rss` feed is its `rank`; search feeds give none), drop seen ids, posts older than 96 hours and posts ranked below 10 in their weekly top feed (rankless search results pass), save `state/reddit/raw/<date>.json`, Haiku scores 50 at a time (two invalid answers give the batch score 0 plus a warning). From posts scoring 3 or more, `selectPosts` takes 10 candidates, in turns per subreddit (orca is one group), best rank first. Their comment feeds are fetched and cached in `state/reddit/comments/<date>.json` (a failure becomes a warning, is not cached and is retried on a rerun). Candidates with fewer than 5 comments, or whose comments failed, are dropped (orca is exempt), and the first 7 remain. Sonnet gets each post with up to 50 comments, or none when fewer than 3 remain without AutoModerator and removed comments, plus the previous 3 days of notes, and returns a highlight and comment summary per post as JSON (two invalid answers fail the run; it may omit repeats). The code renders the note, so titles, links and metrics never pass through the model. Write `output/reddit/<date>.md`, publish to alias `radar-reddit-<date>`.
- Pipeline of `pr_stats`: one GitHub Search API query per ISO week (Monday to Sunday, Taipei time) for merged PRs of the orgs in `config/prStats.yaml`, paged 100 at a time with 2.1 s between requests (search allows 30 a minute; a 403/429 waits for the reset). Counts of every author go to `output/prStats/<YYYY-Www>.json`, overwritten on a rerun; `members` in the yaml only filters what `/prs` shows, so changing it needs no refetch. Search returns at most 1000 results, more gives a warning and `"truncated": true` in that week's file (absent otherwise), which `/prs` shows as 已截斷. Without `--from/--to` it fetches the last 7 days (this week and last). `/prs` shows a team chart (total of the listed members) above the per-member chart, and a table, newest week first, with a total and an average column (the average uses today's member list, not the list of that week). A week without a file is `—`, not 0 (a labelled band in the charts); the current ISO week is dashed and marked 進行中 because it is not final; the page shows when `pr_stats` last succeeded (from `runs.jsonl`) and an invalid `from`/`to`/`weeks` falls back to 26 weeks with a notice. `web` mounts `config/` read-only for the member list.
- Pipeline of `changelog_watch`: sources are listed in `config/changelog.yaml` (kinds `githubReleases`, `markdown`, `githubFile`, `githubSkills`; `jobs/changelogSources.ts` turns each into change items and the next per-source state, stored in `state/changelog/<id>.json`). Releases are new since the stored `published_at` (first run: last 7 days); every other kind is a diff against the stored text (first run: baseline only, listed as 已建立基準). Haiku (system prompt includes `config/changelogContext.md`, the team context maintained by the user) splits each item into single changes with a category and importance 0-3, and also returns the importance 0 ones with a one-line text, so they can be spot-checked in `triage.json` (two invalid answers drop that source for this run with a warning and its state is not advanced); Sonnet gets at most 40 of the changes with importance 1 or more, chosen by `selectChanges`: urgent (棄用/價格) first, then 4 places reserved for each source, the rest by importance, with the same context. A warning says how many were left out, and `output/changelog/<week>.triage.json` lists every triaged change of the week, importance 0 included, with a `selected` flag, also with `--no-upload`: read it to find important changes Haiku wrongly scored 0 before the first real run. The note goes to `output/changelog/<YYYY-Www>.md` and alias `radar-changelog-<YYYY-Www>`. Source state and the week's changes (`state/changelog/weeks/<week>.json`) are saved only after the upload succeeds, so rerunning in the same week rebuilds the note from the saved changes plus anything new instead of replacing it with 本週無重大更新. `--no-upload` writes the note file only.
- Only posts shown in the note are marked seen, and only after the upload succeeds, so a failed run is picked up again by the next one and a post that missed the gates today can pass later in the week. `--no-upload` never marks posts. `--date D` reuses `raw/D.json` when it exists instead of fetching again.
- Pipeline of `dev_weekly`: `jobs/devWeeklyGithub.ts` reads, per repo in `config/repos.yaml`, the PRs merged in the ISO week (Monday to Sunday, Taipei time), the open PRs and the open issues through GraphQL search (cursor variable must be `$endCursor`; a search returns at most 1000 results, more gives a warning), and saves them as `state/devWeekly/raw/<week>.json`, which a rerun of that week reuses (also after `--no-upload`). Merged PRs count whatever their target branch: this team merges into long-lived branches (`amp/master`, `amp/workspaces/<ws>/master`), not `main`. `jobs/devWeeklyRules.ts` holds the fixed rules: a merged PR with fewer than 50 words of description and more than 100 changed lines is read by Opus (at most 10 a week, largest first, lockfiles and generated files dropped from the diff, cut at 30,000 characters; one sentence each, cached in `state/devWeekly/opus/<week>.json`); an open non-draft PR older than 3 days is stuck, a draft without update for 14 days is stale, an open issue without update for 14 days that no PR mentions explicitly (`#12`, `o/r#12`) is listed. One Sonnet call groups the merged PRs into features by integer id; `normalizeGroups` makes every PR appear exactly once (leftovers go to 其他), and two invalid answers fail the run. The code renders the note (`renderReport`), so links, authors and titles never pass through a model. Output `output/devWeekly/<week>.md`, alias `radar-dev-weekly-<week>`; `config/devWeeklyContext.md` (members and workspaces, maintained by the user) goes into the Sonnet prompt. Sends private PR text and some diffs to the Anthropic API.

## CodiMD

CodiMD 2.5 has no HTTP endpoint that writes a named note. `publish()` logs in with email and password, opens the note once so it is created under the user, then writes through socket.io as one operation. This needs `socket.io-client@2.5.0` (the server speaks the old protocol; 4.x fails with "server error"), polling transport only, and the session cookie sent in `extraHeaders`. Pushed content is remembered in `state/codimd/<alias>.md`; if the note on the server differs from that, it was edited on the web and is not overwritten (`editedOnWeb`). The same mechanism is in `~/.claude-shared/scripts/codimd/push.mjs`. Credentials live only in `.env`.

## Constraints that shape the code

- All model calls go through the Messages API with the key from the linked Console org. Interactive Claude Code, the GitHub Action and IDE/desktop launches bill as Claude Code usage and are not covered by the credits.
- Model tiers: Haiku classifies and filters first, Sonnet writes, Opus only where reading large diffs or making comparison judgments, Fable only for `amp_compare --deep`.
- Reddit feeds are RSS only, no API, with a custom User-Agent (do not put contact details in it). RSS has no upvote or view counts (`.json` answers 403 without login), so the popularity gate is the rank in the weekly top feed (feeds are ordered by score) plus the comment count, and the note shows only the comment count, counted from the comment feed and possibly below the real number, and the rank in the subreddit's top feed. Without `limit` a feed returns only 25 entries, so every URL in `config/reddit.yaml` has `limit=100` (verified). Reddit answers 429 after about one request per minute without login; `fetchFeed` waits for `x-ratelimit-reset` plus one second and retries, so a full collection of 21 feeds takes about 20 minutes and the comment feeds of 10 candidates about 10 more. Keep that in mind when scheduling anything after it.
- GitHub sources must go through the API, never scraped HTML; page-to-text for other sources should use a readability library so nav/footer changes do not cause fake diffs.
- A source that cannot be fetched must be flagged at the top of that run's note, never silently skipped.
- Must run on a machine that can reach the internal CodiMD, not GitHub Actions.
